# Language (VI / EN)

## Behaviour

- Cookie: `tasco-locale` (`vi` default, `en` if value is exactly `"en"`).
- Toggle: `src/components/language-toggle.tsx` in both shells. Calls `switchLocale` (`src/app/actions/locale.ts`).
- `switchLocale` sets the cookie, `revalidatePath("/", "layout")`, and if the user is a **customer**, writes `customer.preferredLanguage`.
- `/api/chat` also copies the cookie onto `preferredLanguage` on every request so demo/LLM replies match the UI even if the customer record was stale.
- `<html lang={locale}>` in `src/app/layout.tsx`.

## Dictionaries

`src/lib/i18n/dictionaries.ts` — parallel `vi` / `en` objects. `Dictionary` is `DeepStringify<typeof vi>` so the two trees can differ in literal strings.

Usage on server pages:

```ts
const locale = await getLocale();
const dict = getDictionary(locale);
```

Pass `locale` (and `dict.chat` labels) into client components that cannot call `cookies()`.

Helper `src/lib/i18n/t.ts` exists for dotted keys if needed; most screens use `dict` directly.

## Surfaces already wired

- Marketing home, login, app/marketing shells, nav, watermark, persona pill, mode toggle.
- Staff titles: ops, agent, compliance, metrics, admin, workflow, forbidden.
- Classic chat chrome + chips + opener.
- Verify, VETC, call titles.
- Office CS / Claims / station copy (`office-copy.ts`).
- Demo agent replies (`demo-reply.ts` branches on `preferredLanguage`).
- Onboarding steps (`src/lib/onboarding-steps.ts`).

## When you add a screen

1. Add keys to **both** `vi` and `en` in `dictionaries.ts` (same shape).
2. Read `getLocale()` / `getDictionary()` in the server page for titles.
3. Pass `locale` into client widgets.
4. If the screen talks to the agent, do not introduce a second language toggle (Classic chat used to have a local `Lang:` button; that was removed in favor of the global header).
5. Keyword handlers in `demo-reply.ts` must accept **both** Vietnamese and English chips (`xác nhận` / `confirm`, `thanh toán` / `pay`, `nhân viên` / `human`, `gia hạn` / `renew`).

## Office vs dictionary

JRPG station intros stay in `office-copy.ts` so the 2D layer is self-contained. Shell/nav stay in dictionaries. Do not duplicate the same sentence in both unless it is truly shared.
